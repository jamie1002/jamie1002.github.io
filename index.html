車況之眼 — 智慧巡檢系統

類型：艾鍗學院期末專題　｜　我的角色：前端開發與物件偵測模型訓練　｜　成果展廠商最佳中意獎

問題

車輛租借前後拍照沒有標準，使用者常拍歪、拍糊，甚至沒拍到車也能上傳成功，後台只能靠人力一張張看，異常也很難第一時間抓出來。

做法

我設計了「AI 引導拍攝」流程：手機開啟網頁後載入兩個 YOLOv8n 模型，在瀏覽器端即時判斷拍攝角度、距離與車牌位置，畫面上會即時疊出引導框，提示水平有沒有歪、距離夠不夠、畫面清不清楚，使用者照著對準就能拍出可用的照片。另外針對車牌在傾斜角度下辨識失準的問題，訓練自訂車牌字元辨識模型，取代原本失效的 OCR 方案。

技術架構

  • React + Vite（PWA）
  • TensorFlow.js
  • YOLOv8n ×2
  • 瀏覽器端推論
  • Device Orientation API
  • Canvas 影像處理
  • GitHub Pages

當時的技術選擇

  • 車牌辨識改成自己訓練模型。Tesseract.js 在車牌傾斜的時候幾乎讀不出來，但實際拍攝很難正對車牌。我重新標註資料集，訓練 33 類別的字元辨識模型，mAP50 是 0.989。
  • 模型放在瀏覽器端跑，沒有上傳雲端。引導拍攝需要即時回饋，影像送出去再回來會有延遲，使用者會對不準。放在本機也不用把車輛照片傳出去。代價是模型要夠輕，效能要自己顧。
  • 顯示層和推論層的座標分開換算。CSS 顯示的尺寸跟模型輸入的畫布尺寸不一樣，直接沿用會讓引導框偏掉。我把裁切幾何的計算抽成共用函式，兩邊各自換算。
  • 提示一次只顯示一則。一開始多個提示會同時跳出來，使用者不知道要先改哪一個。改成固定的優先順序（水平 → 垂直 → 清晰度 → 距離 → 位置 → 車牌），只顯示最前面那一則。
  • 模糊判定加上移動平均。單張畫面的清晰度數值跳動很大，提示會一直閃。改成每 300ms 取樣一次、做 EMA 平均後才判定。

訂單規則分類與批次合併

類型：任職億觀生物科技期間之實務專案　｜　我的角色：需求定義、流程設計、開發與測試

問題

原公司需要把多通路的訂單依產品、檔期、合作案等規則手動分類，合併後再登打到 ERP，作業重複又容易出錯，約 30 筆訂單要花一個小時。

做法

我用 Playwright 模擬人員操作 ERP 網頁，依原本的作業規範完成登入、開單、填抬頭、逐項輸入商品、填分析編號到存檔，最後把 ERP 產生的銷售單號回填到 Google Sheets。中間加上一套自己設計的規則引擎負責分類，以及一道人工確認的關卡。

技術架構

  • Python
  • Playwright
  • gspread / Google Sheets API
  • Tkinter
  • logging（每日換檔）
  • Regex

當時的技術選擇

  • 用 UI 自動化，沒有等 ERP 開 API。ERP 是外購系統，要客製介接得走廠商報價和排程，時間不好掌握。用 Playwright 模擬操作雖然比較笨，但當下就能用，也不會動到 ERP 本身。
  • 規則放在 Google Sheets，沒有寫死在程式裡。檔期和合作案每個月都在變，寫死的話每次改規則都要找我。改成表格設定之後，同事可以自己新增規則、調整優先度、開關生效。
  • 用優先度處理規則衝突。一張訂單裡可能有三種商品命中三條規則。我用「品號開頭 + 品名關鍵字」兩個條件比對，再用數值優先度決定最後套哪一條，這樣結果是固定的，不會因為程式先讀到哪一條而不同。
  • 資料驗證用 Fail Fast。只要有必填欄位沒填，就直接停下來並回報是第幾列。跑到一半才失敗，ERP 會留下半套資料，清理起來比重跑一次麻煩很多。
  • 保留人工確認的關卡。會寫進 ERP 的動作，我不想讓它完全自動。執行前會跳出一個可以捲動的預覽視窗，列出每張訂單套用哪條規則、命中什麼條件、出貨日是哪天，確認後才真的開始打單。為了讓中英夾雜的表格對齊，另外寫了計算東亞字元寬度的函式。

成果

原本約 1 小時的人工流程縮短到 3 分鐘內完成，也不會再有人工登打的錯漏。

庫存自動匯出與 BOM 查詢系統

類型：任職億觀生物科技期間之實務專案　｜　我的角色：需求定義、流程設計、開發與測試

問題

前公司的 ERP 只能 5 個帳號同時登入，查詢介面也不好操作，但生管、採購、業務每天都要查庫存和 BOM 結構。實際狀況是大家排隊等登入，不然就是直接來問我。

做法

分成兩段：後端用 RPA 定時登入 ERP 匯出倉庫結餘報表，整理後寫進 Google Sheets 當資料來源；前端另外做一個網頁查詢介面，整合跨倉庫存查詢、安全庫存警示與 BOM 樹狀展開。這樣 ERP 的登入名額只會被排程腳本用掉一個，其他人不需要再登入 ERP。

技術架構

  • Python
  • Playwright（Headless）
  • Pandas
  • gspread / Service Account
  • Google Apps Script
  • Bootstrap / SortableJS
  • 工作排程器

當時的技術選擇

  • 匯出檔用兩種方式解析。ERP 匯出的檔案副檔名是 .xlsx，但實際上是 HTML，read_excel 會直接失敗。我改成先試 Excel 格式，失敗就換 read_html，兩條路都留著。
  • 假設排程一定會失敗。沒有人看著的腳本一定會遇到 ERP 轉太久或網路斷線。內建最多重試 3 次、失敗自動截圖、每天一個 log 檔並清掉 30 天前的紀錄。所有路徑都以腳本所在資料夾為基準，避免排程器從別的目錄啟動時找不到檔案。
  • 帳密放 .env，Google 金鑰用 Service Account。腳本會長期放在公司電腦上執行，不能把帳密寫在程式裡。
  • BOM 先用 ETL 彙整。三個 BOM 來源檔分散在不同的雲端檔案，每次查詢都去讀會太慢。改成一鍵觸發 ETL 寫進本地總表，查詢時只讀一個地方。
  • 前端分批渲染。品項數量多，一次全部塞進畫面會卡住。改成捲到底才載下一批，另外做了多關鍵字搜尋，以及物料類型和產品線的篩選。
  • 每個人有自己的常用清單。用登入的 Email 自動建立專屬分頁，可以自訂常用品項和拖曳排序。生管和採購每天要看的東西不一樣，共用一份清單反而不好用。

成果

庫存資料改成每小時自動更新，查詢從只有 5 人能用變成全員都能查，原本分散在不同檔案的 BOM 也整合到同一個介面。

在億觀生物科技擔任產品工程師期間，我的工作橫跨電商營運、採購、倉儲、生管與品管，每天都有大量重複又容易出錯的 ERP 打單和庫存整理要處理。為了解決這些麻煩，我開始使用 AI 輔助開發，自己定義需求、設計流程，再反覆測試修改到穩定可用，最後做出兩套工具：ERP 訂單自動打單（原本 1 小時的人工流程縮短到 3 分鐘）和庫存自動化匯出（原本只有 5 人能查，改成全員都能透過網頁即時查詢）。這個過程讓我第一次體會到用程式解決真實問題的成就感，也讓我對自動化與資料處理產生濃厚興趣。

主動進修與正式轉職

我於在職時，先報名了 Python 基礎課程，確認自己真的有興趣，才決定正式轉職，離職後報名艾鍗學院的數據分析暨機器學習應用班做系統性的學習；期末專題「車況之眼-智慧巡檢系統」中，我負責前端的開發與物件偵測模型訓練，設計 AI 引導拍攝流程解決拍攝角度不一、沒拍到車輛也能過關的痛點。過程中車牌在傾斜角度下辨識失準，我重新標註資料集訓練了自訂的字元辨識模型取代原本的 OCR 方案，該作品於成果展榮獲廠商最佳中意獎。同一段期間我也自主準備，先後取得 IPAS AI 應用規劃師初級與中級（機器學習）證照。

我能帶來的價值

我累積了非常豐富的實務應用與工作經歷：真實的企業系統（ERP／BOM）操作經驗、跨部門協作與流程設計能力、以及品管測試的嚴謹訓練。做產品驗證時，我的工作包含訂出測試方法、撰寫測試 SOP、判定樣品合不合格，這跟現在做影像檢測、把判定條件交給模型執行，是同一類的問題。背景雖然不是資工本科，但加上現在具備的程式與資料處理能力，我有信心能快速理解實務上的問題，為團隊帶來務實的貢獻。
